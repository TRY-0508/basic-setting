# 外部资源调研与文档规范

大型多域项目推进中，将外部资源（学术 paper、开源项目等）按项目域组织管理，并编写结构化分析文档。

> 本 skill 生成的调研分析文档均遵循 AGENTS.md 中的「个人文档内容偏好」：平实语言、具体而非抽象、不堆砌术语、不用虚饰限定词。

## 0. 触发条件

加载本 skill 的场景：

- 项目中已有或计划建立 `resource/` 目录结构
- 调研资源数量大（30 篇以上），且跨越多个项目域
- 需要对资源进行长期维护和跨模块交叉引用
- 用户明确要求按"域"组织资源、或编写 INDEX.md / OVERVIEW.md

## 1. 目录结构

资源统一存于 `resource/` 下，按**项目域**（而非研究主题）分层组织：

```
resource/
├── INDEX.md                    # 总索引（按域分类的资源地图 + 密度标注）
├── README.md                   # 快速导航
│
├── papers/                     # 学术论文
│   ├── INDEX.md                # 论文总索引（域导航 + 跨域索引 + 统计）
│   ├── <域A>/                  # 每个项目域一个子目录
│   │   ├── OVERVIEW.md         # 五维度分析
│   │   └── *.pdf
│   ├── <域B>/
│   └── cross-domain/           # 跨域架构设计（全域参考）
│       ├── OVERVIEW.md
│       └── *.pdf
│
└── projects/                   # 外部项目
    ├── INDEX.md                # 项目总索引（域导航 + 接入决策树）
    ├── <域A>/                  # 按项目域组织
    ├── <域B>/
    └── cross-domain/           # 多用途基础设施
```

**域清单由项目自身的架构划分决定，本规范不预设固定清单。**

### 分类原则

1. **按域分类**：论文和项目放入对它有**主要参考价值**的域目录下。
2. **允许重叠**：一篇论文对多个域有价值时，放入主域，并在次域的 OVERVIEW 中添加 `[see also]` 交叉引用，注明具体哪个章节对次域有价值。
3. **跨域统一**：面向整体架构设计的论文和项目放入 `cross-domain/`。
4. **理论基础**：方法论基础类资源（如形式化方法、通用架构框架）放入独立的基础目录，不视为域。

## 2. 论文分类与总览文档规范

每个域目录的 `OVERVIEW.md` 必须对每篇论文包含以下五个维度的详细分析：

| 维度 | 中文标识 | 内容要求 |
|------|---------|---------|
| Motivation | **出发点** | 论文要解决什么问题？现有方法为什么不够？目标的领域背景 |
| Innovation | **创新性** | 与现有方法相比的核心差异是什么？技术贡献的独特性在哪里？ |
| Approach | **做了什么** | 具体的技术方案、系统架构、关键算法、实现细节 |
| Validation | **怎么验证** | 实验设置、数据集、基线方法、具体数字（样本量、p 值、提升幅度）、消融实验、局限性 |
| Value | **价值** | 对本项目的具体启示——哪个模块、什么设计方向、可借鉴的具体模式 |

要求：
- "怎么验证"必须包含可引用的具体数字和实验设置，不能只有"验证了有效性"这样的笼统描述
- 每个维度 3-8 句话，信息密度要高，读者看完就能清楚知道这篇 paper 的核心思想和实验方法
- 所有实验数字直接来自原论文，不得伪造
- 文档使用中文编写

## 3. 项目分析文档规范

每个外部项目的独立 `.md` 文件必须包含以下四个维度的详细分析：

| 维度 | 中文标识 | 内容要求 |
|------|---------|---------|
| Motivation | **出发点** | 项目要解决什么问题？目标用户是谁？与现有方案的关键差异 |
| Innovation | **创新性** | 核心技术创新点、独特设计模式、与竞品的差异化 |
| Implementation | **实现内容** | 代码架构、关键组件、技术栈、规模指标（LOC、文件数、贡献者） |
| Value | **价值** | 对本项目的启示——验证了什么设计假设？挑战了什么设计假设？可借鉴什么具体模式？ |

要求：
- 头部信息必须包含：GitHub Stars、许可证、版本号、语言
- 尽可能包含 ASCII 架构图展示核心组件关系
- 必须有"对本项目的关键启示"小节，明确列出验证/挑战/可借鉴点
- 文档使用中文编写

## 4. 新增资源流程

1. **发现新论文/项目** → 判断对哪个项目域有主要参考价值，放入对应域目录
2. **跨域判断**：资源对多个域有价值？
   - 放入**主要参考价值**的域目录
   - 在次要域的 OVERVIEW 中添加 `[see also: {域}/]` 交叉引用，注明具体关联内容
3. **论文**：
   - 更新对应域目录的 `OVERVIEW.md`，按五维度格式添加条目
   - **下载 PDF**：从 arXiv 等开放平台下载（`https://arxiv.org/pdf/{ID}`），保存到对应域目录下。文件命名：`{论文标题}_{Year}.pdf`（空格→连字符）
4. **项目**：在对应域目录下创建独立 `.md` 文件，按四维度格式编写
5. **更新索引**：同步更新 `papers/INDEX.md` 或 `projects/INDEX.md` 中的数量统计和导航
