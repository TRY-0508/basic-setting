# 论文综述生成

将用户指定的研究方向整理为一份高质量的文献综述文档。

> 本 skill 生成的综述文档均遵循 AGENTS.md 中的「个人文档内容偏好」：平实语言、具体而非抽象、不堆砌术语、不用虚饰限定词。

## 核心原则

综述文档的核心方法是**从论文内容出发，自底向上构建叙事**：

1. **先把论文读懂，再动笔。** 先通过阅读（论文摘要页、全文、或已有分析）获取每篇论文的具体内容——它解决了什么问题、怎么做的、发现了什么。不要在没有充分阅读的情况下凭印象拼凑。

2. **从中提取一条发展脉络。** 好的综述不是在讲"有几类方法"，而是在讲"这个领域怎么一步一步走到今天的"。先提出问题背景，然后展示第一波工作发现了什么、第二波工作怎么在它的基础上改进、第三波工作又怎么推翻了前面的假设。读者读完后应该能理解领域的演进逻辑。

3. **每个论断对应到具体的论文。** 陈述"某工作发现了什么"时必须给出该论文的具体实验数字（占比、倍数、提升幅度），不能只写结论不给出处。读者应该能从文档中追溯到每一条结论的来源。

4. **指出冲突和张力，而非只做总结。** 如果论文 A 说"MAS 更好"而论文 B 说"等预算下 SAS 不差"，不要只罗列双方观点。分析为什么结论不同（实验条件不同？未控制变量？），这对读者才有价值。

5. **所有实验数据直接来自原论文，不得伪造或推测。**
6. **输出形式由用户需求决定，不预设固定的章节模板。**

### 任务规模判断

- **有种子论文**（用户提供了论文列表/URL）：跳过逐阶段确认，直接从摘要中提取信息，输出综述 `.md`，PDF 放 `papers/`
- **无种子论文**（需要从零检索）：每个阶段结束后与用户确认再继续

## 二、检索与筛选

### 2.1 检索策略

- 有基准综述时：从综述的参考文献和分类体系出发，定位核心论文
- 无基准综述时：先用 Semantic Scholar 搜索最新高引综述作为起点
- API 查询：`https://api.semanticscholar.org/graph/v1/paper/search?query=关键词`

### 2.2 筛选原则

优先选择 CCF-A/B 或 SCI 期刊论文，覆盖该方向的代表性工作和不同子范式，时间跨度足以展示技术演进。

筛选后应有 10-20 篇核心论文，加上背景引用共 30-50 篇。

### 2.3 文件组织

PDF 命名：`[年份]_[会议/期刊缩写]_[论文缩写]_[第一作者].pdf`

目录按分类组织，记录每篇论文的完整元信息。

### 2.4 论文编号必须二次验证（经验）

**触发条件**：从任何渠道（API、搜索页、子智能体报告、记忆）拿到 arXiv 编号后。

**做法**：
1. 下载 PDF 后，用 pypdf 提取首页文本（Windows 上先设 `$env:PYTHONIOENCODING='utf-8'`），核对真实标题与作者。
2. 编号与标题不符（下载到错误论文）或 PDF 404 时，视为"编号不可信"，重新检索或放弃该论文。
3. 检索时注意：`export.arxiv.org` API 和部分搜索引擎（Semantic Scholar）易被 429 限流；`arxiv.org/search/?searchtype=all&query=...` 网页搜索和 `arxiv.org/pdf/{id}` 下载通常可用。个别论文（如 EMNLP Findings 收录但未传 arXiv 的）在 arXiv 上确实不存在，搜索返回 0 结果时不要硬凑编号。

**原理**：子智能体和 API 返回的编号在真实部署中会出错（实测约 5% 的编号对应错误论文）；论文标题是最终的可验证锚点。

**实例**：一次综述任务中，两个子智能体报告"已用 API 验证"的编号实为物理论文/机器人论文；下载后用 pypdf 逐篇核对首页标题，全部论文的元信息才可信。

**反模式**：直接信任搜索页或子智能体报告的编号，不下载核对就写入参考文献。

## 三、阅读与聚类

### 3.1 分层阅读策略

按论文与核心方向的关联度分层阅读，节省 token：

| 层级 | 关联度 | 阅读深度 | 提取内容 |
|------|--------|---------|---------|
| P0（核心） | 直接相关 | 全文精读 | 核心论点、关键引用、方法论、实验数字 |
| P1（支撑） | 方法/理论支撑 | 摘要 + 结论 + 方法章节 | 贡献要点、与核心方向的关联 |
| P2（背景） | 领域背景 | 摘要即可 | 一句话定位 |

### 3.2 主题聚类

将论文按主题分组为 5-8 个群组，而非按发表时间或方法类型机械排列。同一群组内的论文围绕同一个子问题展开讨论。

聚类后与用户确认分组和阅读优先级，再进入写作阶段。

## 四、写作原则

### 4.1 组织方式

**按主题组织，而非逐篇罗列。** 以下是两种典型组织方式的对比：

| 方式 | 结构 | 效果 |
|------|------|------|
| 论文列表式 | "论文 A 做了 X。论文 B 做了 Y。论文 C 做了 Z。" | 像带注释的参考文献列表，缺乏叙事 |
| 主题聚类式 | "在子问题 P 上，早期工作 A 提出了 X，但存在局限 M。B 通过 Y 改进了 M，但引入了新问题 N。C 则从另一个角度 Z 来解决 P..." | 有观点演进、有冲突、有故事线 |

### 4.2 每篇论文的分析要点

分析每篇论文时覆盖以下方面，但不要求固定的格式顺序：

- **出发点**：解决什么问题？前人方法的不足在哪里？
- **创新性**：核心贡献是什么？与现有方法的本质区别？
- **做法**：技术方案。偏好用表格展示算法流程（步骤 | 操作 | 输入/输出 | 设计意图），比大段文字更清晰
- **验证**：实验设置、关键数字（F1、消融实验结论等），必须是原论文的具体数字
- **局限与价值**：方法有什么不足？对本方向的启示？

### 4.3 叙事驱动

好的综述文档有一条清晰的"故事线"。不是按概念分类（"第一节讲预算、第二节讲记忆、第三节讲路由"），而是按**领域演进的逻辑**组织：

**推荐的叙事结构：**

1. **问题背景**：为什么这个问题重要？用具体的数据或现象回答，而不是"XX 领域很重要"这类空话。数据要包含指标、时间跨度、变化幅度等可查证的信息。
2. **第一波工作：发现和度量**：谁先做了系统性的测量？发现了什么反直觉的现象？
3. **第二波工作：基于发现做优化**：后续工作如何利用第一波的发现？哪些优化是结构性的、哪些是启发式的？
4. **第三波工作：优化自身被自动化**：从手动调参到自动演化、从被动记录到主动干预
5. **冲突与辩论**：哪些论文的结论互相矛盾？为什么会矛盾？（实验条件不同？定义不同？）这个分析对读者最有价值
6. **当前状态与缺口**：我们学到了什么？还没解决什么？

**组织时的要点：**

- 章节标题应该反映"我们知道了什么"而非"有哪些概念类型"。优先用问题式标题（如"消耗发生在哪里？"），不用分类式标题（如"消耗度量维度"）；具体措辞由当次综述的领域决定
- 每个章节内部的论文按"提出→改进→推翻"的逻辑排列，展示观点的演进
- 跨章节之间存在因果关系（第一阶段发现了 X → 第二阶段基于 X 做了 Y），要在过渡处点明
- **避免**的情况：把领域肢解为"预算控制 / 记忆管理 / 路由策略 / 多 Agent 协调"四个平行的概念篮子，然后往每个篮子里扔论文。这样读者看不到篮子之间的联系，也不理解为什么这些篮子同时存在

### 4.4 写作风格

- **通俗解释优先**：引入新概念时用日常比喻辅助理解
- **具体胜过抽象**：表述为"F1 提升 6.2%"而非"取得显著效果"
- **引用可溯源**：每一条论断都要能对应到具体的参考文献
- **区分综述与原创新究**：高引综述论文首次出现时标注 `〔综述〕`

## 五、输出建议

以下是根据常见场景的输出建议，可根据用户需求灵活调整：

### 5.1 场景 A：快速了解一个方向

输出一篇 3000-5000 字的短文：
- 领域背景与核心问题（500 字）
- 方法分类与各方向概览（1500 字，含分类表格）
- 关键论文要点（1000 字，P0 论文的核心贡献）
- 当前挑战与研究方向（500 字）

### 5.2 场景 B：深入技术综述

输出一篇 8000-15000 字的长文：
- 背景与问题定义
- 方法分类体系
- 各子方向深入分析（每个子方向一个章节，包含该方向内论文的横向对比）
- 综合对比表（维度 | 论文 A | 论文 B | ...）
- 开放问题与未来方向

### 5.3 场景 C：PPT 讲稿

在深入综述的基础上，额外输出 PPT 风格的讲稿（`---` 分隔，每段一张幻灯片），适合用于组会汇报。

### 5.4 格式规范

- 标题层级最多四级
- 表格和 Mermaid 图表用于展示对比关系和算法流程
- LaTeX 公式用于数学表达
- 引用格式按用户要求（APA / GB/T 7714 / 编号 `[1]` 等）

## 六、常见错误

- **用概念分类代替发展脉络** — 把领域肢解为"预算控制 / 记忆管理 / 路由策略"等平行篮子，然后往每个篮子里扔论文。读者看不出篮子之间的联系，也不理解为什么这些篮子同时存在。
- **从结论倒推内容** — 先在脑中有了一个分类框架，然后把论文当证据填进去。正确做法是先读论文，让论文的内容决定文档的结构。
- **只有总结没有批判** — 指出冲突、局限、缺口才是有价值的综述。两篇论文结论矛盾时，分析"为什么"（实验条件不同？定义不同？未控制变量？），这个分析本身是最有价值的内容。
- **实验数字笼统** — "显著提升" vs "F1 提升 6.2%"，后者才是可引用的信息，前者是空话。
- **跳过用户确认** — 每个关键决策点（论文列表、聚类、大纲）应与用户确认后再继续。
- **伪造或推测引用数据** — 所有引用必须来自实际论文，实验数字必须来自原论文。
